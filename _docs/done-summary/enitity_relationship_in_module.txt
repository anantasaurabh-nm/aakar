Walkthrough: Generic Reference Resolver & Module Architecture
We have eliminated all hardcoded entity/user checks from core and implemented a fully generic, schema-driven Reference Resolution Architecture. Any module can now reference any other module with zero changes to core code.

1. Architectural Changes
A. Shared Contract Updates
In 
packages/shared-contracts/src/api/entity-schema.ts
:

EntityDefinitionSchema: Added displayField?: string so target entities declare their default label field (e.g. "displayField": "employee_name" in employees).
EntityFieldSchema: Added displayField?: string so reference fields can optionally override which field to display (e.g. "displayField": "username").
B. New Generic Service: ReferenceResolverService
In 
backend/src/core/entity-engine/reference-resolver.service.ts
:

resolveTargetMeta(targetRef, callerDisplayField): Dynamically inspects any <module>.<entity>, determines the table name via tableName(module, entity), and resolves the display column using: $$\text{callerDisplayField} ;\to; \text{targetEntity.displayField} ;\to; \text{standard candidates (name, title, label, username...)} ;\to; \text{first string field} ;\to; \text{'id'}$$
getOptions(targetRef, tenantId, callerDisplayField): Generates dropdown options for form views dynamically.
resolveBatchLabels(targetRef, ids, tenantId, callerDisplayField): Batch-enriches table rows with resolved human-readable display labels (fieldKey + '__label') via a single query.
searchReference(targetRef, tenantId, searchTerm, callerDisplayField): Resolves natural language references for AI chat and returns available options when not found.
C. Core Decoupling
entity-engine.controller.ts
: Removed all hardcoded core.user checks. getForm calls referenceResolver.getOptions(field.entity, user.tenantId, field.displayField).
entity-registry.service.ts
: Removed all hardcoded user table queries. executeList and executeGet call referenceResolver.resolveBatchLabels(...).
orchestrator.service.ts
: Removed hardcoded user table queries. AI uses referenceResolver.searchReference(...) for any referenced entity.
